# Route UI (direction A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the Sweep client to the "Route" design (direction A): a compact rail-and-nodes run view, self-hosted Bricolage Grotesque and Atkinson Hyperlegible type, a flat four-metric bottom bar, redaction-bar spoilers, a "Leave X behind?" clear sheet, and a two-pane 4:3 handheld layout.

**Architecture:** The client is Angular 22.2 standalone components styled with Tailwind 4 utilities that resolve to CSS custom properties in one `@theme` tokens file. The restyle is therefore (1) new token names and values plus fonts and global utilities, (2) new templates and class lists for the run-view components, and (3) new templates for the bottom bar, sheets and dialogs plus a two-pane handheld layout in the run page shell. No store, queue, engine or API code changes. Existing unit tests that assert on class names are updated to the new class names, never deleted.

**Tech Stack:** Angular 22.2 (standalone, signals), Tailwind CSS 4 (`@theme`, `@utility`, `@custom-variant`), Vitest via `ng test`, Playwright (`pnpm e2e`, projects `phone` 390×844 and `handheld-4x3` 1024×768), self-hosted woff2 fonts, `@angular/pwa` service worker.

**Spec:** `docs/superpowers/specs/2026-09-28-sweep-design.md` §5 (amended 2026-09-30 in §5.5, §5.6 and §5.9 for this plan). Visual reference: `docs/design/2026-09-30-route/` (`A-Main.dc.html` phone run view, `A-Clear.dc.html` clear sheet, `A-Handheld.dc.html` 4:3). Where the artboards and this plan disagree, the plan wins (see that folder's README).

## Global Constraints

- Angular 22.2, TypeScript ~6.0 (never TS 7), Node ≥ 24.15, pnpm 10.34.6. Add deps only with `pnpm --filter @sweep/client add …`.
- Client imports only the `@sweep/core` main entry, never `@sweep/core/parse`. No `@HostBinding`, `ngClass`, `ngStyle`, or explicit `OnPush` (`packages/client/CLAUDE.md`).
- **Token-only color.** Components use Tailwind utilities backed by `packages/client/src/styles/tokens.css`. No raw hex anywhere outside `tokens.css`, `index.html` (`theme-color`) and `public/manifest.webmanifest`. The Tailwind default palette stays disabled (`--color-*: initial`).
- **Not Material.** No pills (`rounded-full` on buttons or chips), no floating action buttons, no `shadow-*` elevation, no glows, no filled tonal chips, no radius above 6 px except the circular checkbox and rail nodes. Status is shown by text color or a 2 px rule.
- **Sentence case** in all UI copy and labels. No `uppercase` / `tracking-*` label styles. Metric labels are "Here", "Now", "Closing", "Last chance".
- **Type:** `font-display` (Bricolage Grotesque) for section titles, page titles, metric numbers and the primary button; `font-body` (Atkinson Hyperlegible) for everything else. Self-hosted only; no `fonts.googleapis.com` anywhere in the client.
- **Touch targets ≥ 44 px** on phone (checkbox rows are 42 px min-height inside the panel, per the artboard; their hit area is the whole row, which is ≥ 44 px with the 6 px category header padding above). Header and bar buttons are 44 px or 48 px.
- **4:3 handheld** is `(orientation: landscape) and (max-height: 800px)` via the existing `handheld:` Tailwind variant. No horizontal page scroll at any size.
- **Accessibility:** AXE clean, WCAG AA contrast on every fg/surface pairing in the tokens. Spoiler text stays in the DOM (visually hidden, `aria-hidden`), and every spoiler goes through `run/spoiler.ts` and `Reveals`. Focus order sensible; `:focus-visible` outline 2 px lamp, offset 2 px.
- **Tests:** unit specs that assert on class names are updated, not deleted. Before every commit: `pnpm lint && pnpm typecheck && pnpm test` from the repo root. E2E: `pnpm e2e` (needs Docker Postgres; it builds `sweep_e2e`).
- **Git:** conventional commits (`feat(client): …`, `test(client): …`, `docs: …`). Stage and commit only, never push. No attribution trailers of any kind.
- The `RunStore` / `WriteQueue` flow, `spoiler.ts`, `reveals.ts`, `lock-reason.ts`, `metric-groups.ts`, `sticky-rows.ts`, `run-actions.ts` are not changed by this plan unless a task names them. Spec interpretations already accepted in `packages/client/CLAUDE.md` stay.

**Rail geometry** (Sections B and C, phone and route pane): rows have `pl-3` (12 px) then a 16 px node column then `gap-2.5` (10 px), so content starts at 38 px; the rail line is absolutely positioned at `left: 19px`, width 1.5 px, `bg-rail`, full height of the list. Node sizes: cleared dot 8 px `bg-rail-dot`; unlocked ring 9 px, 1.5 px solid `border-rail-ring`; locked ring 9 px, 1.5 px dashed `border-rail-ring`; current lamp 14 px `bg-lamp` with `box-shadow: 0 0 0 3px var(--color-surface), 0 0 0 4.5px var(--color-rail-ring)` (this is the only permitted box-shadow; it is a ring, not elevation). Cleared row height 36 px; other rows min-height 44 px; group heading `pl-[38px]`.

**Component interfaces added in this plan** (Section B produces, Section C consumes):

- `app-section-list` gains input `detailPane: boolean` (default `false`). When `true`, no leaf renders as an expanded panel inside the list; the current (or selected) leaf renders as a highlighted compact row (`bg-surface-raised rounded-l-panel`, title in `text-lamp font-display`), and tapping any leaf row emits `selectLeaf` instead of expanding inline. New output `selectLeaf: OutputEmitterRef<string>` (leaf id).
- `app-leaf-card` gains inputs `variant: 'row' | 'panel'` (default `'row'`) and `columns: 1 | 2` (default `1`). `variant: 'row'` is the compact rail row (cleared / unlocked / locked / current-compact / next). `variant: 'panel'` is the expanded card (title, "n open", overview, category lists, walkthrough, actions). `columns: 2` lays the category lists out in a two-column grid (`grid-cols-2 gap-x-8`, categories distributed in order, first half left). Existing inputs and outputs stay as they are.
- Everything else keeps its current selector, inputs and outputs. `run-page` (Section C) composes these on handheld: route pane = `app-section-list [detailPane]="true"`; detail pane = `app-leaf-card variant="panel" [columns]="2"` for the selected leaf (defaults to current; resets to current whenever current changes).

| Session | cwd / worktree | Plan section | Starts |
|---|---|---|---|
| S-A "Route UI — tokens, fonts, shells" | `.claude/worktrees/route-ui-a` (off the plan commit on `worktree-route-ui`) | Section A | on G0 |
| S-B "Route UI — run view" | `.claude/worktrees/route-ui-b` (off S-A's G1 commit) | Section B | after G1 |
| S-C "Route UI — bar, sheets, handheld, baselines" | `.claude/worktrees/route-ui-c` (off S-A's G1 commit) | Section C | after G1; C5–C7 after G3 |

Gates (a session stops at each and reports in ten lines):
G0 plan and spec amendment approved by the user · G1 S-A's tokens, fonts and global utilities committed and green (SHA relayed to S-B and S-C) · G2 S-A's page shells and run header committed and green · G3 S-B's run view committed, phone e2e green (SHA relayed to S-C; S-C rebases) · G3-C S-C's C1–C4 checkpoint · G4 S-C's handheld layout, e2e and baselines committed and green · G5 merge via merging-worktrees-into-master (S-A, then S-B, then S-C, onto `worktree-route-ui`, then onto master; never push).

Rulings protocol: a session that hits an ambiguity asks the orchestrator with a recommended answer; it never guesses silently and never re-opens decided items. Rulings are appended, numbered, to the Rulings section above.
Compaction points: after each gate (`/compact keeping only your plan section, the rulings, commit SHAs, and open items`).

Session-tool note: this orchestrator runs without the `spawn_task` / `set_session_*` tools, so each child is an Opus agent started with its section brief and continued at each gate by message. Effort and output style are set in the brief instead of by session settings.
