Extracted from `2026-09-30-route-ui.md` (Global Constraints, Shared contract, Rulings, Review Focus, Section B). Owner: S-B.

## Global Constraints

- Angular 22.2, TypeScript ~6.0 (never TS 7), Node ≥ 24.15, pnpm 10.34.6. Add deps only with `pnpm --filter @sweep/client add …`.
- Client imports only the `@sweep/core` main entry, never `@sweep/core/parse`. No `@HostBinding`, `ngClass`, `ngStyle`, or explicit `OnPush` (`packages/client/CLAUDE.md`).
- **Token-only color.** Components use Tailwind utilities backed by `packages/client/src/styles/tokens.css`. No raw hex anywhere outside `tokens.css`, `index.html` (`theme-color`) and `public/manifest.webmanifest`. The Tailwind default palette stays disabled (`--color-*: initial`).
- **Not Material.** No pills (`rounded-full` on buttons or chips), no floating action buttons, no `shadow-*` elevation, no glows, no filled tonal chips, no radius above 6 px except the circular checkbox and rail nodes. Status is shown by text color or a 2 px rule.
- **Sentence case** in all UI copy and labels. No `uppercase` / `tracking-*` label styles. Metric labels are "Here", "Now", "Closing", "Last chance".
- **Type:** `font-display` (Bricolage Grotesque) for section titles, page titles, metric numbers and the primary button; `font-body` (Atkinson Hyperlegible) for everything else. Self-hosted only; no `fonts.googleapis.com` anywhere in the client.
- **Touch targets ≥ 44 px** on phone (checkbox rows are 42 px min-height inside the panel, per the artboard; their hit area is the whole row, which is ≥ 44 px with the 6 px category header padding above). Header and bar buttons are 44 px or 48 px.
- **4:3 handheld** is `(orientation: landscape) and (max-height: 800px)` via the existing `handheld:` Tailwind variant. No horizontal page scroll at any size.
- **Accessibility:** AXE clean, WCAG AA contrast on every fg/surface pairing in the tokens. Spoiler text stays in the DOM (visually hidden, `aria-hidden`), and every spoiler goes through `run/spoiler.ts` and `Reveals`. Focus order sensible; `:focus-visible` outline 2 px lamp, offset 2 px.
- **Tests:** unit specs that assert on class names are updated, not deleted. Before every commit: `pnpm lint && pnpm typecheck && pnpm test` from the repo root. E2E: `pnpm e2e` (needs Docker Postgres; it builds `sweep_e2e`).
- **Git:** conventional commits (`feat(client): …`, `test(client): …`, `docs: …`). Stage and commit only, never push. No attribution trailers of any kind.
- The `RunStore` / `WriteQueue` flow, `spoiler.ts`, `reveals.ts`, `lock-reason.ts`, `metric-groups.ts`, `sticky-rows.ts`, `run-actions.ts` are not changed by this plan unless a task names them. Spec interpretations already accepted in `packages/client/CLAUDE.md` stay.

**Global utilities** (Section A, `styles.css`): `btn` (transparent, 1 px `border-border`, `rounded-control`, min-height 44 px, `text-fg`, 14 px), `btn-primary` (`bg-lamp text-on-lamp font-display font-semibold`, no border, `rounded-control`), `btn-danger` (`bg-missed text-on-lamp`, kept for Delete run), `btn-quiet` (no border, `text-fg-muted`), `field` (`bg-surface border-border rounded-control`), `menu-item` (unchanged semantics, new tokens), `ck` (the 22 px circular checkbox: `appearance-none`, 1.5 px `border-rail-ring`, `rounded-full`, checked = `bg-accent border-accent` with an inline check mark drawn via `checked:` background SVG in currentColor `on-accent`), `.sheet` (bottom: `border-t border-border`, no radius, `bg-surface-raised`; handheld: right panel 480 px, `border-l border-border`, no radius), `.redaction` (inline-block, height 13 px, `bg-redaction`, `rounded-[2px]`).

**Rail geometry** (Sections B and C, phone and route pane): rows have `pl-3` (12 px) then a 16 px node column then `gap-2.5` (10 px), so content starts at 38 px; the rail line is absolutely positioned at `left: 19px`, width 1.5 px, `bg-rail`, full height of the list. Node sizes: cleared dot 8 px `bg-rail-dot`; unlocked ring 9 px, 1.5 px solid `border-rail-ring`; locked ring 9 px, 1.5 px dashed `border-rail-ring`; current lamp 14 px `bg-lamp` with `box-shadow: 0 0 0 3px var(--color-surface), 0 0 0 4.5px var(--color-rail-ring)` (this is the only permitted box-shadow; it is a ring, not elevation). Cleared row height 36 px; other rows min-height 44 px; group heading `pl-[38px]`.

**Component interfaces added in this plan** (Section B produces, Section C consumes):

- `app-section-list` gains input `detailPane: boolean` (default `false`). When `true`, no leaf renders as an expanded panel inside the list; the current (or selected) leaf renders as a highlighted compact row (`bg-surface-raised rounded-l-panel`, title in `text-lamp font-display`), and tapping any leaf row emits `selectLeaf` instead of expanding inline. New output `selectLeaf: OutputEmitterRef<string>` (leaf id).
- `app-leaf-card` gains inputs `variant: 'row' | 'panel'` (default `'row'`) and `columns: 1 | 2` (default `1`). `variant: 'row'` is the compact rail row (cleared / unlocked / locked / current-compact / next). `variant: 'panel'` is the expanded card (title, "n open", overview, category lists, walkthrough, actions). `columns: 2` lays the category lists out in a two-column grid (`grid-cols-2 gap-x-8`, categories distributed in order, first half left). Existing inputs and outputs stay as they are.
- Everything else keeps its current selector, inputs and outputs. `run-page` (Section C) composes these on handheld: route pane = `app-section-list [detailPane]="true"`; detail pane = `app-leaf-card variant="panel" [columns]="2"` for the selected leaf (defaults to current; resets to current whenever current changes).

## Rulings

Numbered rulings the orchestrator makes during the build are appended here. Children never re-open a decided item.

- **R1 (plan):** `accent` stays a token, valued at the open teal `#5fe0c0`, for links, the checked checkbox and the active filter icon. `lamp` is the primary button and current marker. Nothing else is teal-filled.
- **R2 (plan):** The leaf immediately after current in route order shows the hint "Opens after <current leaf title>" under its title, in `text-fg-muted` 12 px, whether its gate is satisfied or not. Other locked leaves show the existing lock reason (`lock-reason.ts`) in the same style. Unlocked non-adjacent leaves show no hint.
- **R3 (plan):** Group headings render per group. A depth-1 group heading is a 12 px `text-fg-muted` row (title, then its own "n of m"). A deeper group heading is `font-display font-semibold` 15/20 with "n of m" in 12 px muted on the right. Headings stay tappable to collapse; fully cleared groups still start collapsed. A collapsed group's rail nodes are hidden with it.
- **R4 (plan):** Cleared leaves are one 36 px struck-through row. Tapping a cleared row expands it as a `panel` without the lamp marker (its node stays the cleared dot) showing "Reopen section". Tapping again collapses it. The spec's "any card can be expanded manually" holds for every state.
- **R5 (plan):** On handheld, the detail pane shows the selected leaf; selecting is tapping a row in the route pane. It defaults to current and snaps back to current when current changes (after a clear or pin). The route pane scrolls to current on open, as the phone view does.
- **R6 (plan):** Screenshot baselines are generated on Linux (the CI and dev platform). Playwright's default snapshot naming (with platform suffix) is kept. Baselines are committed under `packages/client/e2e/screens.e2e.ts-snapshots/`.
- **R7 (plan):** The run-page header subtitle is "<guide title> · n of m cleared" when the guide title differs from the run name, otherwise "n of m cleared". The title is the run name.
- **R8 (plan):** The clear sheet's lead line is "Clearing this section closes n open tasks." (singular "task" when n = 1), followed by " They have no second chance." when every closing task is gone for good. Each row: 8 px dot (`bg-last-chance`), task title (spoiler-aware), "<Category> · here" when the task's home is the leaf being cleared, otherwise "<Category> · <home leaf title>", and on the right "Gone for good" (`text-last-chance font-bold` 12 px) or "2nd chance at <X>" (`text-fg-muted` 12 px). A locked leaf adds the §5.4 locked warning line in `text-missed` above the rows. The footer note is "Everything else here stays open." Buttons: "Stay here" (`btn`) and "Clear anyway" (`btn-primary`). Undo toast behaviour is unchanged.
- **R9 (plan):** `btn-danger` survives for Delete run only. The `clear-dialog.spec.ts` assertion "Clear anyway has `btn-danger` and not `btn-primary`" flips to "has `btn-primary`".

- **R10 (G1):** Review Focus 1's `offline.e2e.ts` font check belongs to C6, not Section A or B.
- **R11 (G1):** the Bricolage font file's internal name is left as fetched; CSS loads it by `@font-face` family name.
- **R12 (G1):** unit specs that need a stylesheet's source read it through `packages/client/src/testing/read-client-source.ts` (`readClientSource('styles.css')`), never a `?raw` import (the Angular unit-test builder bundles with esbuild).
- **R13 (G1):** a new worktree lacks the root `.env`; copy it from `/home/joe/dev/sweep/.env` after install.

## Review Focus

Failure modes the spec implies that no task's tests would exercise unless listed here. Each line names the owning task, which adds the test.

1. **Fonts offline (A3):** with the service worker installed and the network cut, the run view still renders in Bricolage/Atkinson. Test: `ngsw-config.json` `app` group's `resources.files` includes `/fonts/*.woff2` (a repo-level assertion in `test/`, see A3), and `offline.e2e.ts` gets a check that `document.fonts.check("600 17px 'Bricolage Grotesque'")` is true after reload while offline.
2. **Long titles in the 340 px route pane (C6):** a 70-character leaf title in the route pane truncates with an ellipsis on one line and never widens the pane or causes horizontal scroll. Test: `layout.e2e.ts` handheld project, seed a long title, assert route pane width 340 and `document.documentElement.scrollWidth === clientWidth`.
3. **Redacted title in the clear sheet and metric sheets (B5, C3):** a `spoiler: true` task that is closing shows a redaction bar in the sheet, not its title, and its `aria-label` does not leak the title. Test in `clear-dialog.spec.ts` and `metric-sheet.spec.ts`.
4. **Zero-state metrics (C1):** with Last chance = 0 the amber rule and color are absent; with 0 tracked categories the bar still renders four zeros. Test in `bottom-bar.spec.ts`.
5. **Current leaf at the very top or bottom of the route (B2):** the rail line still spans the whole list (no gap above the first node or below the last) and "Opens after" never points at a leaf in a different, collapsed group incorrectly. Test in `section-list.spec.ts`: first leaf current → no "Opens after" on it, hint on the second; last leaf current → no hint anywhere.
